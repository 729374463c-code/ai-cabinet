# 内阁 · AI Cabinet

原始内阁框架：由人提出目标，GPT 组织多模型协作，成员独立提供证据和异议，并按风险验收成果。借鉴明代内阁与司礼监的分工，强调及时纠错、保留反对意见与对人负责。

本仓库提供公开的制度、工作流程和接入指引。它不包含私人任务档案、论文材料、账号或可直接使用的服务凭据，也不是开箱即用的自动运行平台。

## 原始项目与派生项目

**AI Cabinet 是原始内阁框架。** 论文写作等是业务派生项目，各自使用独立仓库、计划、材料与权限；“分支”指业务派生关系，并不要求它们成为本公开仓库的 Git 分支。不要向本仓库合并私人论文、批注、访谈、截图或模型原始会话。

公开版从经过审核的通用内容开始独立 Git 历史。旧的私人历史档案继续私有保存，不随公开发布。

## 角色与制衡

| 角色 | 责任 | 不能自行越过的边界 |
|---|---|---|
| 用户（陛下） | 提出目标、约束与验收要求，最终裁决 | 不把模型评分当作客观保证 |
| GPT 首辅 | 接旨、决定是否派单、拆解任务、协调、整合与呈报 | 不隐瞒失败、缺席或重大异议 |
| Gemini 内阁成员 | 材料整理、备选结构、比较角度与初稿 | 能力按具体任务验证，不因新型号就免审 |
| DeepSeek 内阁成员兼监察 | 逻辑、事实边界、反例、独立复核，直接指出错误 | 监察按阶段触发，不无限互相调用 |
| Astra 审查角色 | 复杂、高精度或高影响事项的独立门禁 | 不作为每个小任务的固定尾环，不自行批准自己的主办成果 |
| 豆包司礼监 | 用户的另一沟通渠道、独立审查和披红 | 不属于内阁；不能替用户授予新权限或把转述当成用户授权 |

本项目内所有成员对用户称“陛下”。项目外保持普通工作方式，不套用内阁身份和审批链。

## 一项工作怎样完成

1. **接旨**：首辅明确成果、约束、证据要求、成本与时间边界。
2. **判断是否派单**：简单查询、低风险一步操作由首辅直接完成。只有拆解、并行或独立复核有收益时才分配。
3. **发出任务包**：写明主办、审查者、必要材料、允许工具、输出格式、预算、截止条件和禁止事项。只传本任务需要的内容。
4. **执行与监察**：主办交付成果和可检查证据；DeepSeek 对重要阶段提出反例或错误。接到征询的成员直接回复，避免循环征询。
5. **讨论与修正**：有分歧就定位证据、复现或补测，不能用多数票代替事实。保留尚未解决的异议。
6. **验收**：普通事项由首辅核查；对外发布、权限变更、高影响或关键证据冲突等交 Astra，结论只有“通过 / 修改后复核 / 阻断”。
7. **呈报与记录**：说明完成什么、谁真正参与、验证了什么、仍有什么限制。重要结论写入派生项目自己的文档。

完整任务包与复核方式见 [工作流程](docs/workflow.md)。

## 模型如何迭代

角色不绑定一个永远不变的型号。**同类型、同消耗档、目标任务表现不退步**的新模型，通过真实验证后替换旧模型：

- GPT 日常首辅采用 Sol 系列迭代，例如 `5.6 Sol → 6 Sol → 6.1 Sol`。版本号只用于发现候选，不证明额度消耗相同。以 medium 为日常起点，按当前订阅权限、任务难度和剩余额度调整。
- Astra 在没有同档次或更强且适合门禁工作的后继模型时保持不变；不因 Sol 更新就替换 Astra。推理程度按可用订阅和风险选择，额度不足时如实延期或缩小范围，不伪称完成高精度审查。
- Gemini、DeepSeek 新模型发布后进入相同的核实、对比、切换和回归流程。不能把 Flash 换到旗舰档简单称为“同成本升级”。
- 更新的是本项目的模型映射和相关 profile。普通工作 profile、其他项目及正在运行的任务不随之被改写。

见 [模型更新规则](docs/model-updates.md)。这是后续 agent 的执行规则；本仓库未启用后台定时监控，也不会自行持续检测新发布。

## 接入和凭据

A2A 是 agent 间的通信协议，不等于模型 API。桌面会员或打开客户端不自动提供 A2A 服务。需要实际运行服务、可访问的 Agent Card、身份认证、消息接口和可验收的任务结果。

从 [A2A 接入指南](docs/a2a-setup.md) 开始。Google/Vertex 凭据、DeepSeek 模型 API key，以及 Gemini/DeepSeek 间的 A2A Bearer 都属于私密配置，不能进入此仓库。

公开内容约束见 [SECURITY.md](SECURITY.md)。案例和演示默认使用虚构材料；不把“HTTP 200”或任务 `completed` 当成业务完成。
