# 模型更新与同档替换规则

角色保持稳定，型号允许迭代。新发布触发候选评估，不自动证明新模型适合现有角色。

## 角色更新路线

| 角色 | 更新原则 | 推理程度 |
|---|---|---|
| GPT 首辅 / 日常执行 | Sol 同系列、同消耗档升级，如 5.6 Sol → 6 Sol → 6.1 Sol；按实际任务性能选后继 | 日常 medium 起步；简单任务可降低，复杂任务按计划额度提高 |
| Astra 独立终审 | 没有同档或更强且适合审查的后继就保留当前 Astra；不能以低档新版本替代 | 由可用订阅、支持的等级与风险决定；不得为节约额度伪造已完成审查 |
| Gemini 成员 | 优先当前服务档的后继，验证中文、工具调用、输出格式与实际吞吐 | 只设置接口支持的参数；Flash 与旗舰档分别评估 |
| DeepSeek 成员兼监察 | 优先同档后继，重点验证逻辑、反例、事实边界与 A2A 工具使用 | 只使用账户和服务实际支持的推理选项 |

上表是路由策略，不是现有安装清单。历史型号不代表对所有账号可用；正式 model ID、宿主支持、上下文限制及下线日期必须现场核实。

## 什么叫“同消耗档”

比较输入、输出、推理、缓存、工具调用、重试、延迟和单位合格交付成本。使用 ChatGPT/Codex 订阅时还应比较额度窗口、模型消耗倍率与可用性；API 单价不能代替订阅额度，会员也不自动包含外部厂商 API 额度。

只有证据支持预算和目标任务表现不退步，才能按既定授权做同档替换。价格或额度未知就标为未知，不能凭名称相似认定相同。显著增加成本、改变权限、服务地区或数据处理方式的迁移属于新取舍，应带具体方案交用户决定。

## 后续 agent 的执行步骤

1. **发现**：任务开始、用户通知新模型，或已明确启用的调度触发时查官方发布。这个公开仓库本身不定时轮询。
2. **核实**：确认正式模型 ID、账户访问、订阅/API 接入方式、费率/额度、推理参数及工具兼容性。记录核查日期和官方来源，私人账户信息只写入私有档案。
3. **分档**：判定是原角色的同档后继还是更高/更低档模型；保留现有 Astra，除非其后继达到同档或更强标准。
4. **小样对照**：固定同题、材料与量表，尽量统一运行通道；做多题、必要重复，覆盖实际岗位。独立匿名评阅，公布证据与分歧；一题胜负不能推广为通用能力排名。
5. **备份与试运行**：先备份私有配置、记录旧型号与回滚方式；仅变更目标项目 profile。重要进行中任务固定原版本，避免中途混用模型。
6. **真实验收**：至少验证短文本、结构化输出、工具调用、A2A 正文和需要的跨成员互通。异常正文或分析文字夹带单独记为交付问题。完成状态不等于质量通过。
7. **应用并记录**：通过后更新私有角色映射、agent/profile 配置和实际启用记录；检查宿主是否需要重新加载或重启。公开文档仅更新通用兼容结论，不上传完整本机配置。
8. **失败回滚**：认证、限流、工具契约、格式、质量或预算发生回归时恢复旧配置，按同样路径验证恢复，并呈报原因。

同档且低风险的已授权更新不必反复索要批准。终审模型本身的替换、权限/数据边界或重大预算变化必须独立复核；不能让唯一候选模型自行批准替换自己。

## 推理程度与订阅

采用当前套餐允许、能通过验收的最低必要等级。用户偏好 medium 并不保证每款模型都接受这个参数；升级后检查支持列表。套餐不支持或余额不足时说明限制，保留未完成标记，不能擅自购买额外额度。主会话、子代理与外部 A2A agent 分别确认实际运行型号。
