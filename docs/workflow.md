# 内阁工作流程

## 接旨与拆解

首辅先判断能否直接完成。需要协作时，在私有任务档案中使用以下任务包：

```text
目标与交付物：
验收标准：
主办 / 独立复核：
必要材料与可信来源：
允许工具、数据范围、禁止事项：
时间与资源预算：
输出格式与事实不确定性标记：
停止条件 / 失败上报 / 重试上限：
```

一项任务只有一位主办负责整合。成员可提议变更，但不能无边界增派任务。默认至多一轮同僚征询；更长协作链由首辅明确允许。技术硬限制若未实现，只能称为约定，不能当成权限隔离。

## 监察与纠错

DeepSeek 对方案、阶段成果和重要变更执行监察，重点询问：

- 结论是否可由给定证据推出，是否混淆事实、推断与行动建议？
- 是否把样本结果外推、把相关性写成因果、或隐去反例？
- 是否因格式整齐就忽略数据错误、执行失败或任务越权？
- 是否可以用更少调用完成相同交付？

审查意见也要复核。评委可能误读数字或过度挑错；首辅须说明采纳、拒绝或待补证的理由。不得用权威角色、平均分或人数替代证据。

## 验收与呈报

A2A 接入验收至少包括：正确的 Agent Card、实际消息发送、目标成员真实推理、可提取正文/产物，以及符合请求的结果。需要跨成员调用时另测互通。无效正文、限流说明或错误回执不算任务完成。

普通成果由首辅核查。复杂设计、重要正式内容、对外发布、资金/权限、安全或不可逆影响等送 Astra。门禁为“通过 / 修改后复核 / 阻断”，并列依据、剩余风险和重大异议。最终由用户决定是否接受成果。

豆包可在用户操作下主动连接已开放的 A2A 服务，承担独立传达与审查。单向可连接不保证双方可主动唤醒；代理间转述不能扩大原始授权。

## 档案和业务派生

原始框架仅保存通用制度。每个派生项目维护自己的目标、任务计划、来源、配置、预算、成果和审查记录。不得把私人论文当作原始框架的公开案例，或自动合并派生项目的私有分支。需要展示时重新生成虚构演示并审查。
