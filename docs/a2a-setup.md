# A2A 接入与工作区隔离

这是部署指南，不包含运行中的服务地址或完整 Hermes 配置。使用的 A2A SDK、Hermes 版本与鉴权语法必须以安装版本的文档为准。

## 三种不同的认证

- Google/Vertex 模型认证：访问模型服务所需的账户、项目与身份凭据。
- DeepSeek 模型认证：访问模型服务所需的 API key 等凭据。
- A2A 认证：agent 服务之间的 Bearer 等身份凭据。

它们不能混用。A2A token 不会自动提供模型调用权限，模型 API key 也不应当作 A2A 的共享口令。为不同成员和用途使用独立凭据，存放在系统密钥管理或本地受保护配置中。

## 部署步骤

1. 安装支持所需 A2A 版本的 agent 服务，创建独立内阁 profile，例如 `cabinet-gemini`、`cabinet-deepseek`。
2. 通过服务原生认证流程配置模型访问。真实 Google 账户、云项目 ID、服务账号文件和 API key 留在本地。
3. 内阁 profile 只开放任务需要的工具；普通工作 profile 使用各自权限，不继承首辅调度规则。项目文件夹归组不等于权限隔离。
4. 服务优先监听回环地址。需要跨机器时使用受认证的 HTTPS 接入，限制来源、权限与日志；不要为了连接方便公开裸端口。
5. 在服务端和客户端分别配置对应的 A2A 身份凭据。不要把它们放在 Agent Card、URL 查询参数、截图或 Git 仓库。
6. 检查 Agent Card 指向正确的 RPC 接口；按该版本协议发送最小消息，读取实际任务正文。
7. 进行需要的工具调用和成员互通测试，确认失败能停止并上报。不要把每条消息都继续转发给另一个成员。

本地可使用独立的环境文件；[示例](../examples/credentials.env.example)只列用途，变量名是部署约定，不能假称任意 Hermes 版本都会自动识别。根据版本把它们映射到原生配置，绝不把替换后的文件提交。

网关启动后可按本地政策保持运行；重启、登录启动与公网访问必须由部署方明确配置。本文不代表这些服务已在读者机器上启动。

## 验收与排障

认证失败先区分模型认证与 A2A 认证；配额失败检查对应项目与模型，不交换成员密钥“试试”。工具缺失检查 profile 权限与模型工具契约。对异常内容保留私有证据并脱敏报告，不能直接上传整份配置或原始会话。
